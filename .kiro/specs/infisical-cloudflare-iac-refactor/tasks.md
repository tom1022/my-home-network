# Implementation Plan

本計画は design.md の Migration Strategy（Phase 0〜6）に対応する。タスク番号の順序が依存関係を表し、
`(P)` を付したタスクは直前の同階層タスクと並行して実施できる。

依存方向の規則（`Secrets → Provisioning → Host Config → Cluster Bootstrap → GitOps → Applications`）は
全タスクの制約として常に有効であり、右向き以外の依存を導入する実装は設計違反として扱う。

- [ ] 1. 不可逆性への備えとシークレットの移送

- [x] 1.1 Infisical プロジェクトの初期化とシークレット命名規約の確定

  - Cloudflare の認証情報を DNS-01 用（既存・最小権限）と Terraform 用（新規・広域）に分離して保持する方針を一覧に反映する

- [x] 1.2 vault から Infisical への移行スクリプトの実装

  - 平文でコミットされている k3s node token を git の追跡内容から回収し、移送対象に含める
  - キー名のみを表示する事前確認モードと、移行済みファイルの追跡を解除するモードを備える
  - Vault パスワードは対話取得し、プロセス引数に載せずに復号処理へ渡す

- [x] 1.3 シークレットの移送実行と解決の検証

  - 同一キーへの再投入が上書きとして安全に繰り返せることを確認する
  - 投入後のシークレット一覧を 1.1 の対応表と突き合わせ、欠落がないことを確認する

- [x] 1.4 証明書と削除対象データの保全

  - 完了状態: 証明書 Secret の退避ファイルが手元に存在し、削除対象ごとにデータ退避の要否が判断済みである

- [ ] 6. Terraform state の外部保管への移行

- [ ] 6.1 state バックエンドへの接続と移行

  - 実行モードをローカルとし、構成計画と適用を作業者の環境で行う構成にする
  - Terraform の必要バージョン指定を、接続方式が要求する水準へ引き上げる

  - 認証は資格情報ファイルではなく Infisical が供給する環境変数から行い、作業マシンにログイン状態を持たない構成にする
  - バックエンド側の変数機構に秘密を保持せず、シークレットの供給元を Infisical に限定することを確認する
  - 並行更新がロックにより排他されること、および過去の state が保持され復旧経路が存在することを確認する
  - 完了状態: state 移行後の構成計画が差分なしを出力し、ローカルの state ファイルに依存せず適用できる
